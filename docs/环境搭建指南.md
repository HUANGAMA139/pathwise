# 迭代 1 · 环境搭建指南（Windows 11 家庭版）

> 你已装好 JDK 和 Maven，所以本指南从「装 Docker」开始。
> 预计 1.5—2 小时，其中 WSL2 安装和重启占大头。

## 本轮的验收标准

跑完这五步，你应该能做到：

1. `docker compose ps` 看到两个数据库都是 `healthy`
2. 能从命令行连进两个库，并确认向量库的 `vector` 扩展已启用
3. `mvn spring-boot:run -Dspring-boot.run.arguments=--sdaq.smoke.enabled=true` 打印出「冒烟测试通过」
4. `git log` 能看到第一次提交

**四条全绿才算过。** 尤其第 3 条别跳过——它是唯一能证明「API Key 真的能用」的证据。

## 第 1 步 · 装 Docker Desktop（约 40 分钟，含重启）

Windows 11 **家庭版没有 Hyper-V**，所以 Docker 必须走 **WSL2 后端**。这一步是全程最容易卡住的地方，按顺序来。

### 1.1 先装 WSL2

用**管理员身份**打开 PowerShell（开始菜单搜 PowerShell → 右键 → 以管理员身份运行），执行：

```powershell
wsl --install
```

这条命令会自动装好 WSL2 和一个 Ubuntu 发行版。装完**必须重启电脑**。

重启后打开 PowerShell（这次不用管理员），验证：

```powershell
wsl --status
```

看到 `默认版本: 2` 就对了。如果显示版本 1，执行 `wsl --set-default-version 2`。

> **如果 `wsl --install` 报错**：多半是 Windows 版本太旧。执行 `winver` 看版本号，需要 21H2 及以上。不够就先更新 Windows。

### 1.2 装 Docker Desktop

到 [docker.com 官网下载 Docker Desktop for Windows](https://www.docker.com/products/docker-desktop/)，安装。

安装向导里**务必勾选 `Use WSL 2 instead of Hyper-V`**——家庭版只能选这个。

装完启动 Docker Desktop，等左下角鲸鱼图标变成**绿色**（表示引擎已就绪）。首次启动会要你登录或跳过，跳过即可。

验证：

```powershell
docker --version
docker run hello-world
```

看到 `Hello from Docker!` 就成功了。

> **拉镜像很慢或超时？** 国内直连 Docker Hub 经常不通。配置镜像加速：Docker Desktop → 右上角齿轮 Settings → Docker Engine，在 JSON 里加：
> ```json
> {
>   "registry-mirrors": ["https://<你的ID>.mirror.aliyuncs.com"]
> }
> ```
> 这个地址在[阿里云容器镜像服务控制台](https://cr.console.aliyun.com/cn-hangzhou/instances/mirrors)免费开通，是当前最稳的方案。**注意：网上流传的一批公共加速器（中科大、网易等）大多已停止服务，别照抄过时的教程。**

## 第 2 步 · 起两个数据库（约 10 分钟）

### 2.1 建立项目结构

**先明确一件事：`smart-data-qa` 就是整个项目的名字。** 根目录名、Git 仓库名、Maven 里的 `artifactId`，三者保持一致（后面 Docker 镜像名也会用它）。

注意这里有个容易困惑的细节：目录叫 `smart-data-qa`（带连字符），但 Java 包叫 `com.example.smartdataqa`（不带连字符）——因为 **Java 包名不允许有连字符**。同一个东西的两种写法，不是两件事。

下面三种做法挑一种。

#### 做法 A：解压起步包（最省事，第一次推荐）

把起步包 zip 解压，把得到的 `smart-data-qa-起步包/` 文件夹**改名成 `smart-data-qa`**，就完成了。里面的目录结构是完整的。

#### 做法 B：用 Spring Initializr 生成骨架，再覆盖（更规范）

好处是会自动生成 Maven Wrapper（`mvnw`、`mvnw.cmd`）和 `src/test/` 目录，这两个后面都用得上。

1. 打开 [start.spring.io](https://start.spring.io/)
2. 按下表填写
3. 点 `Generate` 下载 zip，解压出 `smart-data-qa/`
4. 把起步包里的这些文件覆盖进去：`pom.xml`、`src/main/resources/application.yml`、两个 `.java` 文件、`docker-compose.yml`、`docker/`、`.gitignore`、`.env.example`、`README.md`

| 字段 | 填什么 |
|---|---|
| Project | Maven |
| Language | Java |
| Spring Boot | 3.5.7 |
| Group | com.example |
| Artifact | smart-data-qa |
| Name | smart-data-qa |
| Package name | com.example.smartdataqa |
| Packaging | Jar |
| Java | 17 |
| Dependencies | **先留空**（DashScope 依赖我们手动加进 pom，向导里选不到） |

> 用 IDEA Ultimate 的话，`File → New → Project → Spring Boot` 是同一个向导，填法完全一样。

#### 做法 C：手动建目录

```powershell
# 在你想放项目的目录下执行
mkdir smart-data-qa
cd smart-data-qa

mkdir docker
mkdir -p src/main/java/com/example/smartdataqa
mkdir -p src/main/resources
mkdir -p src/test/java/com/example/smartdataqa
```

**这里有一条必须记住的规则**：Java 的包名和目录是**一一对应**的。包叫 `com.example.smartdataqa`，文件就必须放在 `src/main/java/com/example/smartdataqa/` 下。放错位置会编译不过。用 IDE 新建类时它会自动帮你放对，手动建目录就要自己注意这一点。

> **为什么要用 `com.example`？** 这只是默认占位符。做简历项目可以换成 `io.github.你的GitHub用户名`，看起来更正式。要改的话，包名和目录要一起改。

### 2.2 为什么是两个库而不是一个？

你可能觉得「一个 PostgreSQL 里建两个 database 不就行了」。用两个容器是有意的，两个原因：

**第一，为 迭代 21 做准备。** 到那时你要给 SQL 加安全边界——让 Agent 生成的 SQL 只能碰业务库。物理隔离（两个容器）比配权限省心得多，而且更接近真实生产：你不会把向量库和业务库放在同一台机器上让 Agent 随便连。

**第二，出问题好排查。** 一个库炸了不影响另一个。

代价只是多占一点内存，很划算。

### 2.3 启动

在 `smart-data-qa/` 目录下：

```bash
docker compose up -d
```

等十几秒，然后：

```bash
docker compose ps
```

**成功的标志**：两个容器的 `STATUS` 都显示 `Up ... (healthy)`。

> 如果显示 `starting`，等 10 秒再执行一次。如果显示 `unhealthy`，执行 `docker compose logs pgvector` 看报错。

### 2.4 验证数据库真的能用

连进向量库，确认 `vector` 扩展装上了：

```bash
docker exec -it sdaq-pgvector psql -U sdaq -d rag_db -c "\dx"
```

**成功标志**：列表里能看到 `vector`。看不到就说明 `init-rag-db.sql` 没执行（通常是因为数据卷已存在，初始化脚本只跑一次——执行 `docker compose down -v` 清掉数据卷再重来）。

再连业务库确认它是空的但活着：

```bash
docker exec -it sdaq-business-db psql -U sdaq -d business_db -c "\dt"
```

显示 `Did not find any relations.` 就对了——业务表要到 迭代 18 才建。

**两张库的连接信息**（后面写代码要用）：

| | 主机 | 端口 | 库名 | 用户 | 密码 |
|---|---|---|---|---|---|
| RAG 向量库 | localhost | 5432 | rag_db | sdaq | sdaq_dev_pwd |
| 业务库 | localhost | 5433 | business_db | sdaq | sdaq_dev_pwd |

## 第 3 步 · 申请 DashScope API Key（约 15 分钟）

### 3.1 开通阿里云百炼

1. 打开[阿里云百炼控制台](https://bailian.console.aliyun.com/?apiKey=1&tab=api#/api)
2. 用支付宝/淘宝账号登录
3. **完成实名认证**——没实名认证拿不到 API Key，这一步卡住过很多人
4. 在左侧找「API-KEY」菜单，点「创建我的 API-KEY」
5. 复制生成的 Key（形如 `sk-xxxxxxxxxxxx`）

> **关于费用**：新用户有免费额度，够你跑完整个计划的大部分实验。后续充值 10—50 元也够用很久——qwen-plus 的价格很低。真花光了你会在控制台看到提示，不会静默扣费到爆。

### 3.2 设置成环境变量

**Windows 上推荐用系统环境变量**，而不是 `.env` 文件——因为 IDE 和命令行都能直接读到，不用每次手动加载。

打开 PowerShell（普通权限即可）：

```powershell
setx AI_DASHSCOPE_API_KEY "sk-你的真实key"
```

**重要：`setx` 只对「之后新开的窗口」生效。** 设置完必须关掉当前所有终端和 IDE，重新打开，否则读不到。

验证（新开的窗口里执行）：

```powershell
echo $env:AI_DASHSCOPE_API_KEY
```

能打印出你的 Key 就对了。

> **为什么用 `AI_DASHSCOPE_API_KEY` 这个名字？** 因为 Spring AI Alibaba 认这个名字。你在 `application.yml` 里写的是 `${AI_DASHSCOPE_API_KEY}`，会自动去环境变量里取值——这样代码里就永远没有明文 Key，也不会不小心提交上去。

### 3.3 顺手配一下 Maven 镜像（强烈建议）

国内直连 Maven 中央仓库拉依赖很慢。编辑 `C:\Users\你的用户名\.m2\settings.xml`（没有就新建），在 `<mirrors>` 里加：

```xml
<mirror>
  <id>aliyunmaven</id>
  <mirrorOf>central</mirrorOf>
  <name>阿里云公共仓库</name>
  <url>https://maven.aliyun.com/repository/public</url>
</mirror>
```

这能把首次拉依赖的时间从十几分钟压到一两分钟。注意 `mirrorOf` 写 `central` 而不是 `*`——**如果写 `*` 会覆盖 pom 里配的 spring-milestones 仓库，导致 Spring AI Alibaba 的依赖拉不到。**

## 第 4 步 · 建仓库 + 冒烟测试（约 20 分钟）

### 4.1 初始化 git

```bash
cd smart-data-qa
git init
git add .
git commit -m "chore: 迭代 1 环境搭建（deps/docker/配置骨架）"
```

**提交前先确认 `.gitignore` 生效**：

```bash
git status
```

如果列表里出现了 `target/` 或 `.idea/`，说明 `.gitignore` 没被识别（多半是文件名写错或被系统隐藏了扩展名）。**这一步必须确认**——一旦把 `target/` 提交进去，后面清理很烦。

### 4.2 拉依赖 + 冒烟测试

```bash
mvn clean compile
```

第一次会拉不少依赖，耐心等。**如果有依赖拉不到**，多半是第 3.3 步的 Maven 镜像配错了——检查 `mirrorOf` 是不是写成了 `*`。

然后跑冒烟测试：

```bash
mvn spring-boot:run -Dspring-boot.run.arguments=--sdaq.smoke.enabled=true
```

**成功标志**：日志里出现这两行

```
========== 冒烟测试通过：API Key 有效、模型可访问 ==========
```

以及模型的回答和耗时。

> 这个测试默认是**关闭**的（在 `application.yml` 里 `sdaq.smoke.enabled: false`），只有显式加参数才跑——避免你之后每次启动都白花一次 token。

### 4.3 再正常启动一次

```bash
mvn spring-boot:run
```

确认不带参数也能干净启动、没有报错。然后 `Ctrl+C` 停掉。

## 附：项目结构详解（每个文件是干什么的）

**先说一个背景，它能解释一半的疑问：这是 Maven 项目的标准目录结构。** Java 世界有一套大家约定的布局——代码放哪、配置放哪都有固定位置。IDE 和 Maven 靠这套约定自动找东西，所以那些路径不是随便定的，也不能乱挪。

理解这点之后，这些文件只有三类：

- **指挥工具干活的配置文件**：`pom.xml`、`application.yml`、`docker-compose.yml`、`.gitignore`、`.env.example`
- **给人看的文档**：`README.md`
- **真正的代码和数据**：`src/` 下的东西、`docker/init-rag-db.sql`

下面逐个说。

### 根目录层

**`smart-data-qa/`**
项目根目录，就是整个项目本身。所有东西都装在它里面。

**`pom.xml`**
Maven 的配置文件（pom = Project Object Model）。干两件事：一是**列出项目需要哪些第三方库**，二是**告诉 Maven 怎么打包**。

你用了 Spring AI Alibaba，这库不是 JDK 自带的，得在这里告诉 Maven「去网上把它下下来」。里面反复出现的 `<groupId>` + `<artifactId>` + `<version>` 三件套就是「坐标」，相当于说清楚「出版社 + 书名 + 版次」，Maven 靠这三个才能找到正确的库。

**`application.yml`**
Spring Boot 的**运行参数**。写着端口 8080、日志级别、API Key 从哪个环境变量读。

为什么不直接把端口写死在 Java 代码里？因为改配置不用重新编译、不用重新打包。这是「配置与代码分离」原则，也是 12-Factor 里的一条。

**`docker-compose.yml`**
告诉 Docker「帮我起两个数据库」。里面写了用哪个镜像、端口怎么映射、密码是什么、数据存哪。

一条 `docker compose up -d` 同时起两个库，比手敲两条 `docker run` 省事，也方便别人复现你的环境。

**`.gitignore`**
一张清单，告诉 Git **哪些文件不要提交**。比如 `target/`（编译产物）、`.idea/`（IDE 配置）、`.env`（你的密钥）。

**这个文件不是可选项。** 不写它，`git add .` 会把编译垃圾和密钥一起提交。**把 API Key 提交到 GitHub 是真实会发生的安全事故**——GitHub 上有机器人专门扫这个，扫到会通知阿里云，你的 Key 可能被直接停用。开头带点的文件（`.gitignore`、`.env.example`）在 Linux/Mac 上是隐藏文件，Windows 上默认可见。

**`.env.example`**
密钥和配置的**模板**。它写着「你需要配哪些变量」「格式长什么样」，但**值是假的**。用法是复制成 `.env`，填上真的。

为什么要有它：别人（或者半年后的你）拿到这个项目，看一眼就知道要配什么。真的 `.env` 被 `.gitignore` 挡住了，不会泄露。

**`README.md`**
项目说明书。前面第 5 步专门讲过，这是你简历的一部分。

### `docker/` 目录

**`docker/init-rag-db.sql`**
一段 SQL，作用是**启用 pgvector 扩展**。

为什么需要单独一个脚本：PostgreSQL 装好之后是个「空壳」，向量能力（`vector` 数据类型）默认是关着的，得执行 `CREATE EXTENSION vector;` 打开。这个脚本会在容器**第一次**创建数据时自动跑一次——注意是「第一次」，之后重建容器不会重跑，这也是常见坑表里那条「看不到 vector 扩展」的原因。

### `src/` 目录

**`src/`**
source 的缩写，所有源代码都在这。名字必须是 `src`，Maven 靠它认路。

**`src/main/java/`**
放 **Java 代码**的地方。里面那串 `com/example/smartdataqa/` 不是随便建的——它是**包名翻译成目录**：包叫 `com.example.smartdataqa`，目录就得是 `com/example/smartdataqa`，一层对一层。这是 Java 的硬规矩，放错会编译不过。

**`SmartDataQaApplication.java`**
整个程序的**入口**。里面有 `main` 方法，程序从这开始跑。

你可能注意到它几乎是空的，只有几行。它的作用是「标记」：`@SpringBootApplication` 这个注解告诉 Spring「从这个类所在的位置开始扫描，把周围的组件装配起来」。所以它虽然不干活，但没有它程序起不来。

**`EnvSmokeRunner.java`**
冒烟测试，迭代 1 用来验证「API Key 能用、模型能访问」。

它被 `@ConditionalOnProperty` 控制着，**默认不跑**，只有你显式加参数才执行——避免以后每次启动都白花一次 token。等 迭代 2 开始写真正的 Agent 循环后，它基本就没用了，但留着不碍事。

**`src/main/resources/`**
放那些**不是 Java 代码、但程序运行时需要读**的文件：配置文件、SQL 脚本、提示词模板等。Maven 会自动把这里的东西打进最终的 jar 包。

### 一张速查表

| 文件 | 什么时候会动它 |
|---|---|
| `pom.xml` | 需要加新依赖时（比如 迭代 18 要加 JDBC） |
| `application.yml` | 改配置时（端口、日志、连接信息） |
| `src/**/*.java` | 天天改，这是你的主要工作区 |
| `docker-compose.yml` | 基本不动，除非换端口或加服务 |
| `.gitignore` | 偶尔加规则 |

## 常见坑速查

| 症状 | 原因 | 怎么修 |
|---|---|---|
| `wsl --install` 报错 | Windows 版本低于 21H2 | `winver` 看版本，先更新系统 |
| Docker 启动后鲸鱼图标一直是橙色/红色 | WSL2 没装好或没重启 | 重启电脑；`wsl --status` 确认版本为 2 |
| `docker compose up` 卡在拉镜像 | 国内直连 Docker Hub 不通 | 配阿里云镜像加速器（见 1.2 节） |
| 端口 5432 被占用 | 本机已装过 PostgreSQL | 改成 `5433:5432` 和 `5434:5432`，或卸载本机 PG |
| 连进 rag_db 看不到 `vector` 扩展 | 数据卷已存在，init 脚本没跑 | `docker compose down -v` 清卷后重来 |
| `echo $env:AI_DASHSCOPE_API_KEY` 为空 | `setx` 后没重开终端 | 关掉所有终端和 IDE，重新打开 |
| Maven 拉依赖超时 | 没配镜像 | 见 3.3 节 |
| 依赖 `com.alibaba.cloud.ai:*` 找不到 | 要么没配 `<repositories>`，要么 Maven 镜像 `mirrorOf` 写了 `*` | 检查 pom 里的 `<repositories>`；把 `mirrorOf` 改成 `central` |
| 冒烟测试报 401 / 403 | Key 错了或没实名认证 | 回控制台重新生成 Key，确认已实名 |
