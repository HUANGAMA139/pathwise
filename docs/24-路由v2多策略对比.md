# v24 · 路由 v2：多策略对比（准确率 × 延迟 × 成本）

> 目标：把 v9 那个 **8 题的预演**，做成 **28 题 × 5 策略 × 三个维度** 的正式对比。
> 新增：`router/DataSourceManifest` · `router/HybridQueryRouter` · `router/EmbeddingPrototypeRouter`
> · `eval/TokenMeter` · `eval/UsageMeterAdvisor` · `agent/RouterBenchmarkDemo`
> 改动：`config/AgentConfig`（清单生成搬进 `DataSourceManifest`）
> 开启方式：
> ```
> mvn spring-boot:run "-Dspring-boot.run.arguments=--sdaq.exp24.enabled=true"
> ```
> **状态：已实跑。** 结果与发现见第五节。

---

## 一、为什么不能只看准确率

计划里那句话就是本轮的题眼：

> 一个 95% 准确但每次要 2 秒 + 花 token 的方案，未必比 88% 准确但 20ms 免费的好。

**只报准确率的对比表，会系统性地偏向「调大模型」那一边**——因为准确率免费，延迟和钱不免费。
所以本轮必须把三个维度都摆出来。

还有一个更基本的理由：**「LLM 比关键词好」这句话，在 v9 就只有 8 道题撑着。**
8 题上差 3 道，换个测试集可能就没有了。本轮用 28 题、并且把成本也摆上桌。

## 二、六个策略（A / A2 / A3 是同一个 LLM 路由的三种「喂什么」）

| | 策略 | 是什么 | 一句话 |
|---|---|---|---|
| **A** | LLM + 清单 | 产品路径（v23 起） | 准确率上界，但要花 token |
| **A2** | LLM 无清单 | = v9 的形态（提示词里那份硬编码清单） | 用来量 **v23 那个清单值多少** |
| **A3** | LLM + 清单**带内容提示** | 清单里给每份文档补一句「它讲了什么」（取它自己的二级标题） | **实验臂**（2026-10-09 补）：和 A 只差提示词那一段，见 5.3.1 |
| **B** | 关键词规则 | `KeywordQueryRouter`，手写词表 | 零 token、零延迟，**零泛化** |
| **C** | 混合 | 规则给单一类就采信，`both`/`refuse` 转 LLM | 省调用，但**继承规则的全部误判** |
| **D** | embedding 原型 | 把问题投到 4 个「路由原型」上取最近 | 零**生成** token，一次 embedding |

**C 的判据为什么是「命中形状」而不是置信度**：规则路由的置信度是固定值（命中 0.6 / 没命中 0.5），
它只会说「匹配到了没有」。所以只能看形状——`document`/`database` 是凭具体词命中的，采信；
`both`（两类都沾）和 `refuse`（一类都不沾）**恰是它自己最含糊的两处**，交给 LLM。
（v8 实测过：把「销售额是怎么算的」误判成 `both`，结果答案里多了个没人问过的数字。）

## 三、三个维度怎么量

| 维度 | 怎么量 | 注意 |
|---|---|---|
| **准确率** | 实际路由 vs testset 的 `expected_route` | 28 条上 **±2 条 ≈ 0.071**（本节 §5.3 三次复跑后修正；v15 初测是 ±1 条），小于 2 条的差不可声称 |
| **延迟** | `System.nanoTime()` 包住一次 `decide()` | 规则亚毫秒；LLM 1.5～2.5 s；D 一次 embedding |
| **成本** | 给 ChatClient 挂 `UsageMeterAdvisor`，累计 prompt/completion token | **拿不到 usage 时记 0 会被单独报出来**——「成本 0」和「没花钱」不能长得一样 |

**¥ 列为什么默认留空**：单价写在 `application.yml`（`sdaq.router-bench.price-per-1k-*`），**默认 0 = 不折算**。
**我刻意没给默认价**——没核过的价写进配置，和没核过的话写进文档一样糟。填上你核过的价就折成钱了。

## 四、两个必须说明的偏差

**① D 不是「真本地」。** 计划里写的是「本地小分类器（本地跑）」，但本项目**不引入本地模型权重**
（那要带几百 MB 的模型，也和「主 Java」的定位不搭）。所以 D 实际是**「用一次 embedding 代替一次生成」**——
便宜一两个数量级、也快得多，但**仍要一次网络往返**。把这条写清楚，比含糊地叫它「本地分类器」诚实。

**② D 的原型不能用测试集当训练样本。** 拿 28 条用例做最近邻是**拿测试集训练**
（D13/D15 本就是「同一事实两种问法」），1-NN 会刷出接近满分——**而那个分毫无意义**。
所以原型用的是**四条路由的定义 + 例子**（零样本），没有这个问题。

**③ A 必须和产品路径同源。** 它的清单来自 `DataSourceManifest`（产品路径用的也是它），
不是这里另拼一份——否则比出来的不是策略差异，是提示词差异。这也是把清单从 `AgentConfig` 搬出来的原因。

## 五、结果（实跑）

```
mvn spring-boot:run "-Dspring-boot.run.arguments=--sdaq.exp24.enabled=true"
```

### 5.1 对比表

| 策略 | 准确率 | 平均延迟 | prompt tok | compl tok | 元/次 | 说明 |
|---|---|---|---|---|---|---|
| **A** LLM+清单 | **0.96 (27/28)** | 1862 ms | 878 | 71 | — | 产品路径 |
| **A2** LLM无清单 | 0.89 (25/28) | 1730 ms | 730 | 66 | — | v9 形态 |
| **B** 关键词规则 | **0.50 (14/28)** | 0 ms | 0 | 0 | — | 零 token、零延迟 |
| **C** 混合 | 0.86 (24/28) | 1296 ms | 627 | 50 | — | 转 LLM 20/28 次 |
| **D** embedding原型 | **0.54 (15/28)** | 140 ms | 0 | 0 | — | 零生成 token |

**「元/次」留空是因为单价没配——不是「不要钱」。**

> ⚠️ **表里是「一次跑」的数。** A 和 C 都带 LLM 调用，**多次跑会摆动**——
> A 实测在 **25~27** 之间、C 在 **23~24**；**B 和 D 是确定性的，三次完全一致**。
> **三次复跑的完整对比见 5.3。**

### 5.2 ★ 计划里那个权衡问题，本轮的答案

> 一个 95% 准确但每次要 2 秒 + 花 token 的方案，未必比 88% 准确但 20ms 免费的好。

**在这批数据上，答案是「值」——但不是因为 A 快，而是因为便宜那两个「不是差一点，是不能用」。**

- D：**13 倍快、零生成 token**，但准确率 0.54。**它把 4 道 `both` 题全判错**
  （X01→database、X02→document、X03/X04→database）——而 `both` 正是本项目存在的理由。
- B：**零延迟零成本**，但 0.50——**它把 D 系列语义题全判错**（一个词都没命中就 refuse）。

**便宜的那个只要准确率掉到 0.5，快和免费就一文不值**：路由错 = 走错数据源 = 答案错，
用户拿到的不是「慢一点」，是**一个错答案**。所以「权衡」只在**两边准确率接近**时才成立
（如 88% vs 95%）——本轮这两条廉价路线的差距太大，根本进不了权衡区间。

### 5.3 ★★ 三次复跑：差 2 条在噪声边缘 —— 而且**噪声来自哪一侧也查清了**

**A（0.96）比 A2（0.89）高 2 条**，差在 D10 和 D14（矩阵：A2 这两条 refuse，A 这两条对）。
听起来正好印证「清单有用」——**但先别下这个结论**。

**因为这个对比后来又跑了两遍（2026-10-09），把三次摊开是这样：**

| 哪一次 | A | A2 | **A−A2** | A 错了哪几道 | A2 错了哪几道 |
|---|---|---|---|---|---|
| v23 重跑（文档记载） | 25 | 25 | **0** | — | — |
| **本次（原始）** | **27** | 25 | **+2** | D12 | D10, D12, D14 |
| 复跑①（21:43） | **26** | 25 | **+1** | D12, D14 | D10, D12, D14 |
| 复跑②（21:51） | **25** | 25 | **0** | D12, D14, **D15** | D10, D12, D14 |

→ **A−A2 的差在 0 / 1 / 2 之间游走，均值约 1 条。整体收益不可声称。**

**★ 四条结论：**

**① 噪声不在 A2，全在 A。** A2 **三次的错题集完全相同**（D10 / D12 / D14），准确率**恒为 25/28**；
而 A 在 **27 → 26 → 25** 之间摆，摆动的题是 **D14 和 D15**。
→ **「同一策略两次跑差 2 条」这句话，具体差在哪，现在知道了。**

**② D10 是铁的。** A 判对 **3/3**（全 `document`），A2 判错 **3/3**（全 `refuse`）；
加上 v23 那两场，是 **A 三次全对、A2 四次全错，零例外**。
→ **清单在「模型以为手上没有」这类问题上是确实有用的。**

**③ ★★「净效果 0」被复现了。** 看 A 与 A2 的**错题差集**：

| 哪一次 | 清单**救回** | 清单**弄坏** | 净 |
|---|---|---|---|
| 原始 | D10、D14 | — | **+2** |
| 复跑① | D10 | — | **+1** |
| 复跑② | **D10** | **D15** | **0** |

最后一行**复现了 v23 那个观察**（「修好 D10、弄坏 D15、净效果 0」）——这是它第一次被独立复现。
机制一致：**清单给的是「标题」，不是「覆盖范围」**——
D10 的答案在《产品线与编码规则》里，**标题恰好提示内容** → 救回；
D15 的答案在《数据仓库使用说明》里（讲的是 T+1 延迟），**标题不提示「实时性」** →
模型带着清单逐条找、找不到「像」的，**反而更有底气地拒答**。

**④ 清单不是免费的。** 它每次让 prompt 多约 **150 token**（880 vs 732），
**换回来的收益只有 0～1 条、还在飘。**

> ★ 顺带一个**不要过度解读**的点：A 的准确率看着像在降（27→26→25），
> **但三个点说明不了趋势**——很可能只是回归。**这本身又是一次「小样本别下结论」。**

**复现方式**：`--sdaq.exp24.enabled=true` 连跑三次即可——逐题结果**自动追加**进
`eval/router-compare.csv`（它有 `run` 列，多次跑不覆盖）。

> 这正好是 v23 那条教训的加强版：**汇总行会骗人，逐题也会**（同一策略换个时间就没准了）。
> 小样本上要报的不仅是准确率，**还得报它的摆动范围**。

### 5.3.1 ★★ 后续实验：把「覆盖范围」也给清单（A3）

5.3 有个负面的机制结论：**清单给的是「标题」，不是「覆盖范围」**——
所以它救回 D10 的同时，可能弄坏 D14/D15。

**那就把「覆盖范围」也给它。** 加了一个实验臂 **A3**：清单里给每份文档补一句「它讲了什么」：

```
· 销售区域划分规则（含：区域与省份对应关系 / 历史调整记录 / 区域的存储形式 / 常见误解）
· 数据仓库使用说明（含：数据刷新频率 / 核心表说明 / 查询注意事项 / 常见误解）
```

**提示从哪来**：**不硬编码**，直接取文档自己的**二级标题**——它本来就是文档的一部分，**不会另外过期**
（这正是 5.3 里「手写清单会过期」那条教训的正面解法）。

**三次跑的结果：**

| 运行 | A | A2 | **A3** | **A3−A** |
|---|---|---|---|---|
| ① | 26 | 25 | **27** | **+1** |
| ② | 26 | 25 | **26** | **0** |
| ③ | 26 | 25 | **27** | **+1** |

**★★ 最干净的证据是 D14（「福建以前是哪个区的」）：**

| | ① | ② | ③ |
|---|---|---|---|
| **A**（只给标题） | ❌ refuse | ❌ refuse | ✅ document |
| **A3**（带提示） | ✅ document | ✅ document | ✅ document |

**A：1/3 对；A3：3/3 对。**

**机制正好对上假设**：D14 的答案在《销售区域划分规则》里——**而那份文档的二级标题里，正好有「历史调整记录」**。
A 只看到标题，逐条找、找不到「像」的 → **拒答**；A3 看到「历史调整记录」 → **一击命中**。

**代价**：A3 的 prompt token **880 → 1043（+163，约 +18.5%）**。

**而且 A3 的错题几乎只剩 D12**（`{D12}` / `{D08, D12}` / `{D12}`）——**就是 5.4 那道五个策略全错的争议题**。

> ★ **结论**：**方向明确**——内容提示确实能救回「内容在、标题不提示」的题；
> **但整体只涨 0~1 条，仍落在噪声边缘**（和 5.3 的「清单值多少」同一个处境）。
> **不同的是：这一次机制看得见，代价可量化。**
>
> ⚠️ **还没做成产品路径**——只跑了三次。按项目纪律「量过才开」，要多次复跑取稳定值再定。

### 5.4 ★★ D12：五个策略全错 —— 这不是策略问题

逐题矩阵里 **`D12 [X database]` 出现在每一列**：

```
D12   [X database]  [X database]  [X database]  [X database]  [X database]
```

「每个订单平均贡献多少钱」——**五条路线（含最强的 LLM）全都当成「算一下平均值」→ 走数据库**，
而测试集的期望是 `document`（客单价定义）。

**这值得怀疑测试集**：测试集的 note 写着「刻意不用『客单价』三个字」——目的是考语义泛化。
但结果是**连最好的策略也读成 database**，说明**「不带术语时这句话确实更像数据问题」**。
这和 v22 的 B02/B03/X04（题面缺时间范围）是同一类问题：**期望标注本身可争议。**

→ **挂进待办：D12 的 `expected_route` 要么补一句说明、要么把题面改得更明确。**
**但在改之前不要动它**——改了会牵动 v15 以来所有路由数字。

### 5.5 B 与 C：一个干净到可以拿去讲课的对照

**B（0.50）的失败形状极整齐**：它把 `database`/`both`/`none` 三类**全判对**（那些题都有它的关键词），
把 `document` 里的语义题**全判错**（D03—D08、D10—D15 基本都 refuse——一个词都没命中）。
**「零泛化」这四个字，这一列就是它的定义。**

**C（0.86）正好演示了那个取舍**：转给 LLM **20/28 次**（省了 8 次调用 ≈ 29%），
但**比 A 少 3 条**——丢在 D02、D07、D12 上，而这三条全是**规则给了"确信的单一类"、却给错了**。
这精确印证了设计时那句话：

> C 的准确率上界是 A，不可能超过——它省的是钱，不是准确率。

**29% 的调用换 3 条准确率，这笔账在本轮是不划算的。**

### 5.6 D 的失败模式：又见「分数挤在一起」

D 只错在两类，但错得很彻底：

- **4 道 `both` 全错**：X01/X03/X04→database、X02→document。**「既要数字又要口径」的句子，
  在向量空间里更靠近 database 原型**（前半句的「销售额多少」占了主导）。
- **`document` 里的语义题错一片**（D03/D04/D05/D08/D09/D13/D14/D15→database）。

而且**余弦分全挤在 0.436～0.754** —— **v14 那条「相似度分数挤在一起、阈值兜底走不通」
在路由这一层又出现了**。（同一个物理原因：embedding 打分分布天然窄。）

→ **结论**：原型法能分开**粗类**（database vs refuse 这种差得远的），
分不开**细类**（both vs database、document-语义 vs database）——**而细类正是本项目的命门。**

### 5.7 延迟这一列

A 1862 ms · A2 1730 ms · C 1296 ms · D 140 ms · B 0 ms。

**D 比 A 快 13 倍、B 比 A 快无穷倍——但它们的准确率是 0.54 / 0.50。**
这一列的价值不在排名，在于**它是「为什么最终选了 A」的证据链里的一环**：
**试过更快的，快 13 倍，但它连 `both` 都分不出来**——这就是选 A 的理由。

### 5.8 ★★★ 扩展集：给「核心集里一条都没有」的两类方向定价（2026-10-10）

**起点是一个诚实的缺口**：核心 28 条里，`database→document` 和「该拒答却硬答」**一条题都没有**——
所以 5.2 那句「错误全集中在 `document→X`」**只能说明「还没看到」，不能说明「不存在」**。

**那就补题。** 但**不能混进 `testset.csv`**——那会让 v15 以来所有 `/28` 一次性失真（见 5.4 那条警告）。
所以单开一个 `eval/testset-ext.csv`（4 条）：**单独跑、单独报、单独落一个 CSV**。

| id | 问题 | 期望 | 考什么 |
|---|---|---|---|
| **B05** | 我们目前合作了哪些供应商？ | `database` | 供应商是**数据**、语料里完全没有；但「合作」像流程 → 可能被送去查文档 |
| **B06** | 我们一共有几个仓库？ | `database` | 问的是**物理仓库**（库里 4 个），**但「仓库」二字和语料《数据仓库使用说明》撞词** |
| **N06** | 预测一下下个季度的销售额大概是多少 | `none` | 两个源里都没有「预测」；**极易被硬答**（查个历史数字就报） |
| **N07** | 竞争对手去年的销售额是多少 | `none` | **外部数据**；易被拿自家数字冒充 |

**结果（跑了四次，96 个判定**零翻转**——这四题上 LLM 判定是稳的，不像核心集的 D14/D15 会飘）：**

| 策略 | B05 供应商 | B06 仓库 | N06 预测 | N07 竞品 |
|---|---|---|---|---|
| **A**（产品路径） | `database` ✅ | `database` ✅ | `refuse` ✅ | `refuse` ✅ |
| A2（过期清单） | **`refuse` ❌** | **`refuse` ❌** | `refuse` ✅ | `refuse` ✅ |
| A3（清单带提示） | `database` ✅ | `database` ✅ | `refuse` ✅ | `refuse` ✅ |
| **B**（关键词） | **`refuse` ❌** | **`refuse` ❌** | **`database` ❌** | **`database` ❌** |
| **C**（混合） | `database` ✅ | `database` ✅ | **`database` ❌** | **`database` ❌** |
| **D**（原型） | `database` ✅ | **`document` ❌** | **`database` ❌** | **`database` ❌** |

**★★★ 三条结论：**

**① 产品路径 A：4/4 全对。** 补题之前只能说「还没看到」——**现在可以说「测过了，而且是干净的」。**

**② 那两个方向确实存在，只是核心集里没题去撞它：**
- **`database→document`**：**D 在 B06 上判成 `document`**（「仓库」撞词那个陷阱，它真掉进去了）
- **`refuse→硬答`**：**B / C / D 在 N06、N07 上全硬答**（判成 `database`）

**③ ★★ 这给「准确性买不来」补了一条最狠的证据——从「量」升到「质」：**

之前那条论据是「廉价路线准确率只有 0.5」，那是**量**的问题。现在看到的是**质**：

> **那些又快又便宜的路线，犯的恰好是最危险的那类错**——
> **硬答**（B/C/D）让用户拿到一个**假数字**；**送错支路**（D）让用户**拿不到答案**。
> **只有产品路径 A，在这两个方向上都不犯错。**

**④ 一个副产品**：**A2（过期清单）在 B05/B06 上判了 `refuse`**——
它断言「清单里没有」，而供应商和仓库**明明在库里**。这是「清单会过期」那个病在**新题上的又一次复现**。

**复现方式**：`--sdaq.exp24.enabled=true`。扩展集**自动跑、单独打印、单独写进 `eval/router-compare-ext.csv`**，
**核心集那一段完全不受影响**。

## 六、局限与诚实边界

- **28 条仍然是小样本，而且实测摆动比假设的大**：同一个策略 A 三次跑 = **27 / 26 / 25**，
  → **run-to-run 噪声 ≈ ±2 条（0.071）**，比 v15 定的 ±1（0.036）更松。
  **所以「A 比 A2 高 2 条」落在噪声边界，不能只凭一次说清单有用**（可复现的只有 D10 那一条）。**详见 5.3。**
- **延迟是单次测量**：受网络抖动影响大，**看数量级，不要看小数点**。
- **C 的准确率上界是 A**：它不可能超过「规则判对的部分 + 转给 LLM 判对的部分」。它省的是钱。
- **D 的置信度是余弦值**，不是概率，别拿它和 LLM 的 confidence 直接比；而且它**分数挤在 0.43~0.75**，阈值兜底走不通。
- **成本只算生成 token**：embedding 在另一条计费线上（小一两个数量级），已单列说明。
