# 迭代 17 · 重排（rerank）与 MMR

> 目标：在粗排召回之上加精排打分，再试 MMR 控多样性；跑 A/B 看两者各自带来什么
> 新增：`tools/DocumentChunks`（映射收敛）· `tools/rerank/`（`LlmReranker` · `MmrDocumentPostProcessor` · `RerankedDocumentTool`）· `agent/RerankCompareDemo`
> 开启方式：
> ```
> mvn spring-boot:run "-Dspring-boot.run.arguments=--sdaq.exp17.enabled=true"
> ```

---

## 一、RRF 和 Rerank 不是一回事（本轮的验收点）

这是高频易混考点，先把话说死：

| | **RRF**（迭代 16） | **Rerank**（本轮） |
|---|---|---|
| 作用对象 | **跨通道**：把向量和 BM25 两路合成一路 | **单一路结果集**：给一批候选重排名次 |
| 依据 | **只有名次**——不读内容、不比分数 | **真的读问题和候选正文**，判断相关性 |
| 成本 | 零成本（纯计算） | 每次要调模型，有延迟和费用 |
| 解决什么 | 两路分数**不可比**、各有偏好时把它们合起来 | 「召回了但排不对」，包括「相关但不回答问题」的片段 |

**一句话**：RRF 是**融合两个检索通道的排名**，Rerank 是**对单一结果集做更精细的重排序**。
两者解决不同问题，**可以叠加**——也正是本轮流水线的形状：

```
召回（vector / hybrid）──取 N 个候选──> 精排（rerank / MMR）──取前 K 个
     粗排：快，看召回                     精排：慢，看质量
```

迭代 16 的负结果恰好给了这个分工一个实证：**RRF 在「两路可信度不相当」时会互相拖累**，
因为它只能比名次；而精排能读正文，所以它不受「等权」这个前提的束缚。

## 二、框架里又只有洞、没有实现

1.1.0 的官方 RAG 文档写得很直白：

> "You can also use the `DocumentPostProcessor` API to post-process the retrieved documents...
> **For example, you can use such an interface to perform re-ranking**..."

`DocumentPostProcessor` 的契约是 `BiFunction<Query, List<Document>, List<Document>>`——
**是一个洞**。1.1.0 的 post-retrieval 模块里只有它一个接口，没有任何实现，
更没有 MMR。所以本轮两个都得自己写（和 迭代 16 的 RRF/BM25 一样）。

**这是这个项目里第三次遇到同一件事**（分块要自己配、RRF 要自己写、精排要自己写）。
它不是巧合：**框架给的是「插槽」，插槽里放什么，恰恰是对业务理解的部分。**

## 三、两个精排器，判的是两件不同的事

```
Rerank：对每个候选问「你回不回答得了这个问题」        —— 判的是【相关性】
MMR   ：在相关性之外还要问「你是不是重复了已选中的」   —— 判的是【多样性】
```

所以它们**不是替代关系**：rerank 让**对的片段往前**，MMR 让**前几名别重复**。

### MMR 要解决的「重复」问题在我们语料里是真实存在的

一条规则常常在多个片段里被反复提到——同一份文档切出来的相邻片段、或者不同文档互相引用
（语料是刻意设计成互相引用的）。所以 top-5 里可能有三段是同一条信息的复述，
**等于把上下文额度浪费掉了**。

MMR 的贪心准则正是为此：

```
每次挑一个 d，使   λ · sim(d, 问题)  −  (1−λ) · max sim(d, 已选中的那些)
                   └── 相关性 ──┘      └────── 和已选的重复度 ──────┘
```

λ=1 退化成普通相关性排序；λ=0 会挑出和问题最不搭的东西。本轮取 0.7（偏向相关性，兼顾去重）。

### LLM 精排为什么只调一次模型

逐个给候选打分也可以，但那样 N 个候选要 N 次调用，而且**不同次调用的打分标准会漂移**
（这一轮心里的 7 分和下一轮的 7 分未必同一回事）。一次给出**相对排序**更便宜也更稳——
它本来就只需要「序」，不需要「分」。

## 四、装配：两个正交的开关

```
召回 sdaq.retrieval.mode  vector | bm25 | hybrid      （迭代 14 / 16）
精排 sdaq.rerank.mode     none   | llm  | mmr         （迭代 17）
```

**为什么是两个独立开关，而不是一档「当前最佳配置」**：这是「靠对比数字说话」的项目，
迭代 15 的基线是 `vector+none`、迭代 16 是 `hybrid+none`、本轮要测的是「在召回之上加精排」。
**如果配置只有一档，前面任意一轮的基线就再也跑不回来了，对比也就无从谈起。**

`RerankedDocumentTool` **只做包装，召回逻辑一行不碰**——它就是靠这一点做到正交的。

### 顺带做了一次小收敛

「Chunk ↔ Document 的翻译」到本轮已经出现第三次（迭代 14 检索结果翻译回来、迭代 16 交给 joiner
融合、本轮交给 post-processor 重排），按项目里那条**三次法则**抽成了 `tools/DocumentChunks`。
**更实际的理由是一致性**：这份映射定义了「元数据里哪个键是业务 id」，
两边各写一份迟早写岔，而写岔的后果是融合或重排**悄悄对不上号**。

## 五、怎么测：沿用 迭代 16 的指标，另加一列多样性

| 指标 | 说明 | 要不要模型 |
|---|---|---|
| `hit@1/3/5` + `MRR` | 和 迭代 16 **逐位可比**——而精排恰恰就是「改变名次」的东西 | ❌ |
| `precision_doc` | 返回片段里来自正确文档的比例 | ❌ |
| **`diversity`** | 返回片段之间的**平均两两余弦**，**越低越不重复** | 只算一次 embedding |

多样性是把 19 个片段**一次性**向量化后本地算的（2 批调用），不是每个结果集重算。

**三条写在前面的纪律**（否则容易把噪声当效果）：

1. **`llm` 档是模型输出，天然带波动**——即使 temperature 设成 0（文档也建议这么做）。
   所以这一档的结论要看**两次跑是否一致**，不一致的地方不能说成「效果」。
2. **精排的天花板是召回池。** 正确片段没被召回的话（候选 10 里没有），精排再对也变不出来。
   看到「+精排没提升」时，先确认那几道题的候选池里到底有没有它。
3. **多样性不是越高越好。** MMR 把相关性让给多样性时命中率会掉，这两列要一起看。

## 六、实测结果

```
配置            hit@1   hit@3   hit@5   MRR     精确率   多样性
vector+none     0.87    0.93    1.00    0.906   0.533    0.675   ← 迭代 14 基线
vector+llm      0.87    1.00    1.00    0.922   0.507    0.687
vector+mmr      0.87    1.00    1.00    0.922   0.493    0.630
hybrid+none     0.73    0.93    1.00    0.847   0.480    0.664   ← 迭代 16 的负结果
hybrid+llm      0.87    1.00    1.00    0.911   0.480    0.683   ← 救回来了
hybrid+mmr      0.87    0.93    1.00    0.917   0.480    0.640
```

### 发现 1（本轮最重要）：精排把 RRF 丢掉的排序找回来了

`hybrid+none` 的 hit@1 是 **0.73**，加了精排之后是 **0.87**——**回到了和纯向量相同的水平。**

这正是 迭代 16 留的第三条方向：**不靠 RRF 融合，把两路都交给精排。**
迭代 16 的机制分析说「RRF 只能比名次，所以在两路可信度不相当时会互相拖累」——
**精排不受这个前提的束缚，因为它真的读问题和正文。**

> **这也是验收点那个「两者可以叠加」的第一手证据**：RRF 先把多路合成候选池（粗排），
> 精排再从池子里按内容挑。**RRF 丢的分，精排能捡回来。**

### 发现 2：但精排**没有**让 hybrid 超过 pure vector

看 MRR 那一列：

```
vector+none   0.906
vector+llm    0.922   ← 最高
hybrid+llm    0.911   ← 追平了 vector+none，但没追上 vector+llm
hybrid+mmr    0.917
```

**精排补上了 RRF 的损失，但关键词通道本身仍然没有带来净收益。**
换句话说：**在这个语料规模上，「加 BM25」这件事的价值是负的——加精排只是把负号抹掉，不是把正号加上。**

这一条和 迭代 16 的结论合起来才完整：**BM25 在这个规模上（19 个片段、IDF 统计极不稳定）
本身就不是一个有用的通道**，所以「怎么融合它」都救不回来。

### 发现 3：精排是**双刃**，它在重新分配名次，不是单调变好

逐题看 `vector+none → vector+llm`：

| 用例 | none | llm | |
|---|---|---|---|
| D07 退了货以后钱什么时候从销售额里减掉 | **1** | **2** | 变差 |
| D11 客户退的钱什么时候少算 | **1** | **3** | 变差 |
| D12 每个订单平均贡献多少钱 | **4** | **1** | 变好 |
| D15 能不能一小时前下的单马上查出来 | **3** | **1** | 变好 |
| 其余 11 题 | 不变 | | |

**2 题变好、2 题变差，净效果体现在 hit@3：0.93 → 1.00。**

**变好的两题能看出精排真在干活：**

```
D12 粗排：03#1, 01#1, 04#0, 06#2, 06#1, ...   精排：06#1, 01#0, 03#1, ...
                                   ↑ 第 5 名       ↑ 提到第 1   期望出处=06 ✓
D15 粗排：01#1, 03#2, 04#0, 04#2, ...          精排：04#0, 01#1, ...
                    ↑ 第 3 名                      ↑ 提到第 1   期望出处=04 ✓
```

**而变差的两题暴露出精排的判错模式：**

```
D11 粗排：03#2, 01#2, 03#0, ...   精排：01#2, 01#0, 03#1, ...   期望出处=03
D07 粗排：03#2, 03#1, 01#2, ...   精排：01#2, 03#2, 03#1, ...   期望出处=03
```

**两题都是把「01-销售数据统计口径说明」的片段提到了前面。** 而 01 是「口径说明」，
语义上和很多问题都沾边——**模型自己也犯了「相关但不回答问题」这个毛病。**

> 这正好接上 迭代 14 发现的那件事：**「相关」和「回答得了」不是一回事。**
> 当时是**向量**把这个毛病带进来的，现在是**精排**也犯。
> **说明这不是某个组件的问题，而是「语义相似度」这个判据本身的局限。**

### 发现 4：MMR 的多样性收益是真的，代价也不小

```
vector+none   多样性 0.675   精确率 0.533
vector+mmr    多样性 0.630   精确率 0.493     ← 更不重复了，但精确率掉了
vector+llm    多样性 0.687   精确率 0.507     ← 反而更重复了
```

**有意思的是 llm 精排让多样性略微下降（0.675 → 0.687，更相似了）。**
这有道理：精排把「最相关的」排前面，而最相关的往往**是同一份文档的相邻片段**——
所以它天然会**聚集**。

**这就把 rerank 和 MMR 的对立关系用数据摆出来了：**

```
rerank：追求相关性  →  片段聚集、多样性下降
MMR   ：追求多样性  →  片段分散、相关性让位
```

**它们不是「叠加」，是「取舍」。** 而 MMR 在这个规模上的取舍还算划算——
多样性降了 0.045，精确率降了 0.04，但 **hit@1 保持 0.87、hit@3 还升到 1.00**（没伤命中率）。

### 发现 5：跨天一致性又被验了一次

`hybrid+none` 这一行是 `0.73 / 0.93 / 1.00 / 0.847 / 0.480`，
**和 迭代 16 逐位相同**（迭代 16 那次也是 0.73 / 0.847 / 0.480）。
两天的代码不同、运行不同，非模型那一档的指标完全一致——**确定性没破。**

### 还没验的：llm 档的波动

上面只有一次跑。**`llm` 那两行的结论必须再看一次跑才敢用**——模型输出有波动，
temperature=0 只是减小它、不是消除它。**下次跑要把 `vector+llm` 和 `hybrid+llm` 逐题对比上一次**，
看那 4 道变了名次的题（D07/D11/D12/D15）是不是稳定地变。

## 七、阶段三检查点：三组数字（迭代 17 收口）

| 组 | 配置 | hit@1 | hit@3 | MRR | 结论 |
|---|---|---|---|---|---|
| **baseline** | `vector+none`（迭代 14） | **0.87** | 0.93 | 0.906 | 起点 |
| **+混合检索** | `hybrid+none`（迭代 16） | **0.73** | 0.93 | 0.847 | **负收益**，机制已定位 |
| **+精排** | `hybrid+llm`（迭代 17） | **0.87** | **1.00** | 0.911 | **把负结果抹平**，但仍未超过纯向量 |

**RAG 支路已有真实检索能力**：pgvector 真实向量检索 + 自研 BM25 + 自研 RRF + 自研 LLM 精排与 MMR，
全部可开关（`retrieval.mode` × `rerank.mode`）、可复现、可用确定性指标度量。**检查点的这个要求达到了。**

**而三组数字讲的故事比「一路变好」更有用**：

> 迭代 16 做了混合检索，**发现它有害**；迭代 17 加了精排，**发现它能补上混合检索的损失、
> 但补不出额外的收益**。合起来的结论是：**在 19 个片段的语料上，关键词通道本身就没有价值
> ——问题不在融合方式，也不在精排，而在通道本身的统计基础太薄（IDF 在 df=2 上没有意义）。**
>
> **这个结论只有在「三组数字都能复现」的前提下才说得出来。**

## 七、局限

1. **语料只有 19 个片段。** 精排的价值在「候选多、噪声大」时最明显；19 个片段里
   候选池本来就不脏，所以**本轮的提升很可能被低估**。
2. **候选池只取 10。** 精排的天花板就是这个数——如果 迭代 16 的正确片段排在 10 名之外，
   本轮无论怎么精排都救不回来。候选数本身是个没扫过的参数。
3. **`llm` 精排每查询一次调用**，成本和延迟要记账（对比 迭代 15 实测的 agent 平均 4.2s，
   这一次调用大约再加 1~2s）。
4. **MMR 的 λ 没扫。** 只测了 0.7。
5. **多样性用的是同一个 embedding 模型**——它的相似度定义未必等于「人类眼里的重复」。
   所以这个指标是**代理指标**，不是「重复度」本身。
6. **文档级指标。** 「找对了文档但找错了片段」仍然测不出来（迭代 16 就撞过一次）。

## 八、阶段三检查点：三组数字

到本轮我们手里有：

| 组 | 配置 | 关键数字 |
|---|---|---|
| **baseline** | `vector + none`（迭代 14） | hit@1 **0.87** / MRR 0.906 |
| **+混合检索** | `hybrid + none`（迭代 16） | hit@1 **0.73**（**负收益**，机制已定位） |
| **+精排** | `llm / mmr`（迭代 17） | 待填 |

**RAG 支路已经有真实检索能力**：pgvector 真实向量检索 + 自研 BM25 + 自研 RRF + 自研精排与 MMR，
全部可开关、可复现、可用确定性指标度量。检查点的这个要求是达到了的。

**而这三组数字本身的价值，恰恰在第 2 组是负的**——它证明我们量的不是「有没有做」，
而是「做了之后到底有没有用」。
